# 层合固化证据台（Cure Evidence Bench）

把**设计铺层、实际铺放记录与固化规范**逐项关联到**可重放**的生产证据：
铺层堆叠（SVG）、材料方向、热电偶曲线（SVG）、炉程阶段、压力/真空记录，
以及每条规范规则对应的证据区间与失败时间范围。

技术栈：Java 17 + Spring Boot 3.5 + SQLite（sqlite-jdbc）+ 原生 SVG（无前端构建）。

## 构建与运行

```bash
# 安装/打包（跳过测试）
mvn -q -DskipTests package

# 演示：先跑自动化测试，再启动服务
mvn -q test && mvn -q spring-boot:run -Dspring-boot.run.arguments=--server.port=5557
```

打开 <http://127.0.0.1:5557>，页面标题为 **“层合固化证据台”**。

数据库文件默认在 `./data/cure-evidence.db`（可用环境变量 `CURE_DB` 覆盖）；
空库启动时自动写入固定夹具（`FixtureSeeder`）。

## 固定炉次（Asia/Tokyo，2026-09-18，CYCLE-20260918-01）

- 部件 `P-2609-01` 主翼下蒙皮，8 层铺层 `[0/+45/90/-45/-45/90/+45/0]`，
  材料 `M-CARBON-PREG-A`，批次 `LOT-2026-0711`（证书 CERT-7781），逐层有铺放记录。
- 炉程：升温 08:00–09:30，保温 09:30–12:40，降温 12:40–14:10；每分钟一条热电偶样本。
- 规范版本 `CP-CURE-2024-A`：保温允许带 **175–180°C（闭区间）**，
  **全部必需热电偶共同达标**连续保温 ≥ **120 分钟**；
  升温 ≤ 2.5°C/min；压力 ≥ 0.55 MPa；真空 ≤ -60 kPa；必需热电偶 3 支。

三支必需热电偶**错峰到温**：TC-01 09:20（首点恰为下限 175.0°C）、
TC-02A 09:30（175.0°C）、TC-03 09:38（175.0°C），故共同达标从 **09:38** 起算。
保温期间：

- TC-02A 于 **10:53 被替换**为 TC-02B（10:55 首条恰为上限 180.0°C）→ 证据分割；
- TC-03 在 09:02 有**重复样本**、09:15 后出现 **09:13 时钟回退**样本 → 证据分段；
- TC-03 升温段 08:43–08:44 有 **203/188°C 超温尖峰**（页面可“确认传感器异常”）；
- TC-03 在 12:26 掉至 174.0°C（出带，中断），**12:27 恰为 175.0°C 下限（闭区间判合格）**，12:28 恢复。

共同达标证据段因此为：

| 区间 | 时长 | 说明 |
|---|---|---|
| 09:38–10:52 | 74 分钟 | 三支同时在带；到 TC-02A 最后一条为止 |
| 10:55–12:26 | **91 分钟（最长连续）** | 替换后三支再次共同在带，12:26 TC-03 出带中断 |
| 12:27–12:40 | 13 分钟 | 175.0°C 闭区间样本判合格 |

最长连续 **91 分钟 < 120 分钟**，保温规则失败；逐支在带累计更长（178 分钟），
但**不能把各传感器各自达标时间相加**。初始合规结论为 **不合格（NON_CONFORMING）**。

## 判定口径（数据口径）

1. **共同达标，不做加和**：保温计时从全部必需热电偶在同一分钟格都进入
   `[bandLow, bandHigh]` 后开始；任一支离开即中断。规则使用最长**连续**区间，
   各传感器各自达标时间不允许相加。
2. **闭区间**：样本温度恰好等于上/下限（175.0 / 180.0°C）判为合格。
   样本值按“保持到下一个时间戳”覆盖相邻样本间的分钟格，相邻两点均在带才覆盖该格。
3. **强制证据分割**：时间戳重复（重复样本）、时间戳较前一条回退（时钟回退）、
   传感器替换（同一物理位置链上的不同 tc_id）都必须断开证据段；
   即使断开后两段都在带，也**不拼接**成一段连续保温。
4. **异常确认**：升温段超温尖峰先列为“疑似传感器异常”；确认后从速率/超温
   判定中剔除对应时间窗（R7 完整性事件始终保留，证据段仍分割）。
   确认尖峰只消除 R3 失败，R4 仍因 91 < 120 分钟而失败。
5. **控制点**：页面可选择部件控制点；控制点到温时刻进入 R3 证据，
   选择动作写入 `review_actions` 并改变输入摘要。
6. **偏差分支**：可对失败规则建立偏差处理分支（OPEN → ACCEPTED/REJECTED）。
   总体结论：存在无偏差接受的失败 → 不合格；存在处理中分支 → 偏差处理中；
   全部通过但有已接受偏差 → 合格（含已接受偏差）；全部通过 → 合格。
7. **合规结论留存**：每次评估写入 `evaluation_runs` + `rule_results`，
   包含规范版本、输入摘要（SHA-256 前 16 位，覆盖规范/炉程/样本统计/
   已确认异常/控制点/偏差）、每条规则的证据 JSON 与**每条失败的时间范围**。

规则清单：R1 铺层关联、R2 批次证书有效期、R3 升温/超温（异常剔除）、
R4 共同达标连续保温、R5 保温压力、R6 保温真空、R7 完整性事件与证据分割、
R8 必需位置覆盖率与替换链可追溯。

## 页面操作

- **确认传感器异常**：在“疑似传感器异常”条上确认超温尖峰，评估自动重放。
- **选择部件控制点**：点击 TC-01 / TC-02A / TC-02B / TC-03 切换控制点。
- **建立偏差处理分支**：在失败规则卡片上建立、接受或驳回分支。
- **导出运行记录**：下载全量 JSON（全部数据表，含评估历史与评审动作）。
- **导入复核**：选择导出 JSON，清空当前库并重新导入，然后自动重放评估；
  导入后的输入摘要与导出时一致即证明可重放。
- **清空并重置固定夹具**：删库后重新写入固定演示数据。

```bash
# 命令行复核（服务运行中）
curl -s http://127.0.0.1:5557/api/state | python3 -m json.tool
curl -s http://127.0.0.1:5557/api/export -o run-record.json
curl -s -X POST http://127.0.0.1:5557/api/reset
curl -s -X POST http://127.0.0.1:5557/api/import \
  -H 'Content-Type: application/json' --data-binary @run-record.json
```
